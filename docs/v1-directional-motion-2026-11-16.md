# Directional entrances, scroll reveals and plain labels

V1's navigation and entrance direction share one ordered route list: Home, Projects, Blog, About, Contact. Moving toward an earlier item enters from the right, including Blog → Projects; moving toward a later item enters from the left. The persistent layout remembers the previous path, so browser Back/Forward uses the same rule. Direct loads retain the neutral entrance. List/detail routes belong to their parent section.

The incoming headline, rows and divider origins inherit one direction. The native page boundary provides a short opacity fade, while the contents own the directional movement; it no longer adds a second vertical slide. Stagger delays are bounded at 180ms. The shared shell stays in place, and the CSS entrance also works without the native view-transition API.

Below-screen reveal progress spans 98% to 45% of viewport height. Larger rises and masks make progress more visible. Home project cards and the featured blog post use a media variant with a 94% to 100% scale and a crop reveal. Position maps directly to progress, without a spring or timed queue: stopping holds the reveal, faster scrolling advances it, and completed content stays readable on return. Keyboard focus and reaching the document bottom complete reveals. Reduced motion removes movement and masks; CSS finishes reading entrances without JavaScript.

Public labels, accessible project actions, post navigation, search and empty states, metadata, RSS and CMS labels use Projects and Blog posts. New drafts use `untitled-post-*` and `UNTITLED BLOG POST`; the editor accepts the former draft prefix too, preserving existing draft editing and published URLs. The persisted `caseStudy` field remains an API compatibility detail. Existing authored content is not rewritten. The contact acknowledgment says MESSAGE RECEIVED.

The exact former default site description is translated to the current default when read, so older saved settings do not keep the old terminology in Home's metadata. Custom descriptions and database rows stay intact. The animated tab title now commits in a layout effect alongside the visible alias, closing the frame where a name update could appear before the title caught up.

The direction unit regression failed before implementation and then passed. The new browser assertion was also confirmed to fail against the preceding DEV release. Browser coverage checks real CSS direction, Back/Forward, native-API fallback, reduced motion, stronger early scroll progress, stationary progress, fast completion, no-JavaScript reading and keyboard focus. The two no-JavaScript action checks explicitly verify the containing entrance has settled before the automated click, retaining their original assertions and timeouts.

CI, deployed acceptance, screenshots and recovery evidence belong to the [dated release record](https://docs.home.phao.dev/books/agent-knowledge/page/portfolio-v1-directional-motion-and-plain-labels-16-november-2026). Delivery is scoped to private DEV. Public production and V2 remain separate; no dependency, schema, migration or deployment-helper changes are included. Recovery is a revert through the normal DEV pipeline to the preceding applied revision `84eeac84556ee070d65a0fdd7d0839f4acce6480`, without a source-required database restore. Owner visual review remains separate from technical verification.
